Roadmap do
Desenvolvedor ADS

A jornada de aprendizado de um estudante de ADS até o mercado de trabalho — passo a passo.

Fundamentos

Lógica de programação, algoritmos e estruturas de dados. A base de tudo — sem ela, nada funciona.

Linguagens & Web

Python, JavaScript, HTML/CSS. Construindo interfaces e lógica de servidor, da teoria à prática.

Banco de Dados

Modelagem, SQL, integração com aplicações. Dados são o coração dos sistemas modernos.

Engenharia & Processos

Scrum, Git, documentação, trabalho em equipe. O mercado exige profissionais que saibam colaborar.

Mercado de Trabalho

Portfólio no GitHub, projetos reais, estágio e primeiros empregos. O início da carreira!

Conceitos Essenciais

Definições rápidas dos termos mais cobrados nas disciplinas de ADS.

API REST
Interface que permite comunicação entre sistemas usando métodos HTTP (GET, POST, PUT, DELETE) e formato JSON/XML.
Big-O Notation
Forma de medir a complexidade de um algoritmo em relação ao tamanho da entrada. Ex: O(n), O(log n), O(n²).
MVC
Padrão arquitetural: Model (dados), View (interface), Controller (lógica). Separa responsabilidades no código.
⚡
ACID
Propriedades de transações em BD: Atomicidade, Consistência, Isolamento e Durabilidade.
Git & Versionamento
Sistema de controle de versão distribuído. Permite colaboração, histórico e ramificação (branches) do código.
JWT
JSON Web Token — padrão para autenticação stateless. O servidor assina um token que o cliente usa nas requisições.
☁️
Cloud Computing
Modelos de serviço (IaaS, PaaS, SaaS) que oferecem recursos computacionais sob demanda pela internet.
Design Patterns
Soluções reutilizáveis para problemas comuns no desenvolvimento: Singleton, Factory, Observer, Strategy...
UML
Linguagem de modelagem unificada. Usada para documentar sistemas com diagramas de classe, sequência, caso de uso etc.

API REST
Programação Web
Interface que permite comunicação entre sistemas usando verbos HTTP (GET, POST, PUT, DELETE) e formato JSON. Segue princípios de stateless e recursos identificados por URIs.
Big-O Notation
Algoritmos
Notação matemática que descreve o comportamento limitante de uma função. Mede complexidade de tempo/espaço. O(1) constante, O(n) linear, O(log n) logarítmica, O(n²) quadrática.
⚡
ACID
Banco de Dados
Atomicidade: tudo ou nada. Consistência: dados sempre válidos. Isolamento: transações independentes. Durabilidade: dados persistem mesmo após falhas.
MVC
Engenharia de Software
Padrão arquitetural: Model (dados e regras de negócio), View (interface do usuário) e Controller (lógica de controle). Separa responsabilidades e facilita manutenção.
TCP vs UDP
Redes
TCP: orientado a conexão, entrega garantida e ordenada, mais lento. UDP: sem conexão, entrega não garantida, muito mais rápido. UDP usado em streaming, jogos, DNS.
JWT
Segurança
JSON Web Token: padrão de autenticação stateless. Estrutura: Header (algoritmo) + Payload (claims) + Signature. O servidor assina; o cliente envia em cada requisição.
Git — Branch
Ferramentas
Ramificação independente do código. Permite desenvolver funcionalidades isoladas sem afetar a branch principal. Estratégias: Git Flow (main/develop/feature), GitHub Flow (main/feature).
Normalização
Banco de Dados
Processo de organizar tabelas para reduzir redundância. 1FN: eliminar grupos repetidos. 2FN: dependência total da PK. 3FN: sem dependência transitiva entre atributos.
☁️
IaaS · PaaS · SaaS
Cloud
IaaS: infraestrutura virtual (servidores, redes). PaaS: plataforma para desenvolvedores (runtime, BD gerenciado). SaaS: software pronto para uso final via browser.
OWASP Top 10
Segurança
Lista das 10 vulnerabilidades mais críticas em aplicações web. Inclui: Injection (SQL, NoSQL), Broken Auth, XSS, IDOR, Security Misconfiguration, Componentes desatualizados e SSRF.
UML — Diagrama de Classe
Engenharia de Software
Representa a estrutura estática de um sistema: classes, atributos, métodos e relacionamentos. Associações: herança (triângulo sólido), composição (losango sólido), agregação (losango vazio).

Dúvidas frequentes

FAQ

Perguntas comuns sobre o curso de ADS e a área de tecnologia.

ADS ou Ciência da Computação — qual escolher? +
ADS é mais prático e voltado ao mercado, com foco em desenvolvimento de sistemas, banco de dados e redes. Ciência da Computação é mais teórica, aprofundando matemática, física e fundamentos computacionais. Se você quer trabalhar como desenvolvedor(a) mais rapidamente, ADS é uma ótima escolha.
Qual linguagem de programação aprender primeiro? +
Python é excelente para iniciantes por ter sintaxe limpa e ser amplamente usada em ciência de dados, IA e web. JavaScript é indispensável para o desenvolvimento web. Em ADS, você geralmente aprende ambas durante o curso — o mais importante é entender lógica de programação primeiro.
É preciso saber muita matemática para ADS? +
Mais do que cálculo avançado, você precisará de lógica matemática, matemática discreta, álgebra booleana e noções de estatística. O curso de ADS é bem mais acessível matematicamente do que Ciência da Computação, mas o raciocínio lógico é fundamental.
O que é preciso para conseguir o primeiro emprego na área? +
Portfolio no GitHub com projetos reais, domínio de pelo menos uma linguagem backend e uma frontend, conhecimento básico de banco de dados SQL e soft skills como comunicação e trabalho em equipe. Um estágio durante o curso acelera muito a entrada no mercado.
Front-end, back-end ou full-stack? +
Front-end cuida da interface do usuário (HTML, CSS, JS, React). Back-end cuida do servidor, regras de negócio e banco de dados. Full-stack faz os dois. Para iniciantes, recomenda-se focar em um lado primeiro — full-stack vem com a experiência.
O que é um ODA e como ele funciona? +

Um Objeto de Aprendizagem Digital (ODA) é um recurso educativo interativo para facilitar o aprendizado. Este ODA cobre as principais áreas do curso de ADS — módulos, flashcards, quiz e certificado — tudo em um único arquivo acessível pelo navegador.

Quanto tempo leva para concluir o curso de ADS? +

O curso de ADS tem duração de 2 anos e meio (5 semestres). Na modalidade EAD, como na UNIGRANDE, a carga horária é de 2.000 horas, distribuídas em disciplinas teóricas, práticas e projetos de extensão.

Quais são as principais áreas de atuação do profissional de ADS? +

O formado em ADS pode atuar como: Desenvolvedor Web, Analista de Sistemas, Analista de Banco de Dados, Engenheiro de Software, Analista de Cibersegurança e Analista de Dados. O mercado de TI é um dos que mais crescem no Brasil.

Como se preparar para o mercado de TI ainda durante o curso? +

Dicas práticas: 1) Monte um portfólio no GitHub; 2) Faça certificações gratuitas (Cisco, Google, AWS); 3) Pratique lógica de programação no HackerRank; 4) Participe de comunidades de tecnologia; 5) Contribua com projetos open source. Prática consistente vale mais que certificado isolado.

Módulo 01 · Processos & Qualidade

Engenharia de Software aplica princípios de engenharia ao desenvolvimento de software, garantindo que sistemas sejam confiáveis, eficientes, manuteníveis e entregues no prazo.

Banco de Dados
Módulo 02 · Dados & SQL

Bancos de dados são o coração de qualquer sistema moderno. Compreender modelagem, SQL e as propriedades ACID é essencial para qualquer desenvolvedor.

Tópicos principais
Modelo RelacionalTabelas, colunas, linhas, chaves primarias (PK) e estrangeiras (FK). Diagrama ER para modelar entidades e relacionamentos.
Normalização1FN elimina grupos repetidos. 2FN exige dependência total da PK. 3FN elimina dependência transitiva. Objetivo: reduzir redundância.
SQLDDL (CREATE, ALTER, DROP), DML (SELECT, INSERT, UPDATE, DELETE), DCL (GRANT, REVOKE). JOIN: INNER, LEFT, RIGHT, FULL OUTER.
ACIDAtomicidade, Consistencia, Isolamento e Durabilidade. Garantem integridade mesmo em falhas ou acessos concorrentes ao banco.
NoSQLDocumento (MongoDB), Chave-Valor (Redis), Coluna (Cassandra), Grafo (Neo4j). Flexivel e escalavel horizontalmente.
Índices e PerformanceÍndices aceleram SELECT mas tornam INSERT/UPDATE mais lentos. EXPLAIN analisa planos de execução de queries.
Exemplo SQL prático
-- Consulta com JOIN, GROUP BY e HAVING
SELECT
    c.nome                 AS cliente,
    COUNT(p.id)            AS total_pedidos,
    SUM(p.valor)           AS valor_total
FROM clientes c
INNER JOIN pedidos p ON p.cliente_id = c.id
WHERE p.data >= '2024-01-01'
GROUP BY c.id, c.nome
HAVING SUM(p.valor) > 1000
ORDER BY valor_total DESC;

Redes de Computadores
Módulo 04 · Protocolos & Infraestrutura

Redes de computadores são a espinha dorsal da internet e de qualquer sistema distribuído. Entender protocolos, endereçamento e segurança é fundamental para desenvolvedores modernos.

Tópicos principais
Modelo OSI (7 camadas)Fisica, Enlace, Rede, Transporte, Sessao, Apresentacao e Aplicacao. Cada camada tem funcao e protocolos especificos.
TCP/IPPilha de protocolos da internet. TCP garante entrega ordenada e confiavel; UDP e rapido, sem confirmacao. Base de toda comunicacao web.
Endereçamento IPIPv4 (32 bits, ex: 192.168.1.1), IPv6 (128 bits). Sub-redes com CIDR (/24 = 254 hosts). NAT para redes privadas.
Protocolos de AplicaçãoHTTP/HTTPS (web), DNS (nomes para IPs), SMTP/IMAP (e-mail), FTP (arquivos), SSH (acesso remoto seguro).
Cloud ComputingIaaS (infraestrutura), PaaS (plataforma), SaaS (software). Provedores: AWS, GCP, Azure. Modelos on-premise vs nuvem publica.
Segurança de RedesFirewall, VPN, SSL/TLS. Ataques: DDoS, Man-in-the-Middle, Spoofing. Criptografia simétrica vs assimétrica.
Modelo OSI simplificado
/* MODELO OSI - 7 CAMADAS */

7 Aplicacao    HTTP, DNS, FTP, SMTP, SSH
6 Apresentacao  SSL/TLS, JPEG, MP4, ASCII

4 Transporte    TCP (confiavel) / UDP (rapido)
3 Rede          IP, ICMP, roteamento

Encapsulamento: cada camada adiciona cabecalho
Decapsulamento: cabecalhos removidos na recepcao

Algoritmos e Estruturas de Dados
Módulo 05 · Lógica & Complexidade

Algoritmos são o coração da programação. Saber escolher a estrutura de dados correta e entender complexidade de tempo e espaço é o que diferencia um desenvolvedor mediano de um excelente.

Tópicos principais
Notação Big-OO(1) constante, O(log n) logarítmica, O(n) linear, O(n log n), O(n²) quadrática. Mede crescimento com o tamanho da entrada.
Arrays e ListasArray: acesso O(1), insercao O(n). Lista ligada: insercao O(1), acesso O(n). Pilha (LIFO) e Fila (FIFO) como casos especiais.
ÁrvoresÁrvore binária, BST (busca eficiente), AVL (balanceada). Percursos: pré-ordem, em-ordem, pós-ordem. Heap para filas de prioridade.
OrdenaçãoBubble Sort O(n²), Merge Sort O(n log n), Quick Sort O(n log n) médio. Escolha depende do perfil dos dados de entrada.
BuscaBusca linear O(n) vs busca binária O(log n) que requer array ordenado. Hash Map com acesso e busca O(1) em média.
GrafosBFS (largura) e DFS (profundidade). Dijkstra para caminhos mínimos. Aplicações: redes sociais, rotas, dependências de pacotes.
Busca Binária em Python
def busca_binaria(arr, alvo):
    # O(log n) - divide o espaco de busca pela metade
    esq, dir = 0, len(arr) - 1

    while esq <= dir:
        meio = (esq + dir) // 2
        if arr[meio] == alvo:
            return meio       # encontrado!
        elif arr[meio] < alvo:
            esq = meio + 1   # busca direita
        else:
            dir = meio - 1   # busca esquerda
    return -1               # nao encontrado

# Exemplo: [1,3,5,7,9,11,15], busca 7
# Itera 1: meio=3, arr[3]=7 -> encontrado!

Segurança da Informação
Módulo 06 · Proteção & Compliance

Segurança não é um recurso adicionado depois. É uma prática embutida no desenvolvimento desde o início. Todo desenvolvedor ADS precisa conhecer os princípios de Security by Design.

Tópicos principais
Princípios CIAConfidencialidade (só quem deve acessa), Integridade (dados não adulterados) e Disponibilidade (sistema acessível quando necessário).
CriptografiaSimétrica (AES, mesma chave). Assimétrica (RSA, chave pública/privada). Hashing (SHA-256, bcrypt para senhas — irreversível).
OWASP Top 10SQL Injection, XSS, IDOR, CSRF, Broken Auth, Security Misconfiguration. Guia de referencia para vulnerabilidades criticas em apps web.
Autenticação e JWTSessões vs tokens. JWT = Header.Payload.Signature. Armazenar em httpOnly cookie. Refresh tokens para sessões longas.
LGPDLei Geral de Protecao de Dados (Lei 13.709/2018). Bases legais, direitos do titular, DPO, notificacao de incidentes e multas.
Boas PráticasValidar entrada do usuário, parametrizar queries (evitar SQL Injection), HTTPS sempre, senha com salt+hash, princípio do menor privilégio.
SQL Injection: ataque vs defesa
// VULNERAVEL - concatenacao direta
const q = `SELECT * FROM users WHERE email='${email}'`;
// Ataque: email = "' OR '1'='1" -> retorna TODOS!

// SEGURO - query parametrizada
const q = 'SELECT * FROM users WHERE email = $1';
